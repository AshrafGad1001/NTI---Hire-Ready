Section Three

$group — Employment Rate per Track

db.users.aggregate([
  { $match: { role: "trainee" } },
  { $group: {
      _id: "$track",
      totalTrainees: { $sum: 1 },
      employed: { $sum: { $cond: [{ $gt: ["$monthlyIncome", 0] }, 1, 0] } },
      avgAppliedJobs: { $avg: "$appliedJobsCount" }
  }}
])

Result:

{ "_id": "MERN Stack", "totalTrainees": 3, "employed": 1, "avgAppliedJobs": 14 }
{ "_id": ".NET",       "totalTrainees": 2, "employed": 1, "avgAppliedJobs": 19 }
Real question answered: "Which track leads to more employed graduates — MERN or .NET?" — a question management would genuinely ask.

Section Five

$project — Hiring-Ready Report

db.users.aggregate([
  { $match: { role: "trainee", isActive: true } },
  { $project: {
      _id: 0,
      name: 1,
      track: 1,
      skills: 1,
      readyForHire: { $gte: ["$completedCourses", 8] }
  }}
])

Result: A trimmed report — no email or salary (sensitive data) — with a new computed field indicating whether the trainee is "ready for hire."

Section Nine

$lookup — Matching Job Openings

db.jobs.insertMany([
  { _id: 101, title: "Junior MERN Developer", requiredTrack: "MERN Stack", city: "Cairo" },
  { _id: 102, title: "Junior .NET Developer", requiredTrack: ".NET", city: "Alexandria" }
])

db.users.aggregate([
  { $match: { role: "trainee", isActive: true } },
  { $lookup: {
      from: "jobs",
      localField: "track",
      foreignField: "requiredTrack",
      as: "matchingJobs"
  }}
])

Result: Each trainee now carries a matchingJobs array with openings that match their track — effectively a real "Recommended Jobs" feature.

Section Ten

$facet — Full Dashboard in One Query

db.users.aggregate([
  { $facet: {
      "usersByRole": [
        { $group: { _id: "$role", count: { $sum: 1 } } }
      ],
      "employmentStats": [
        { $match: { role: "trainee" } },
        { $group: {
            _id: null,
            employed: { $sum: { $cond: [{ $gt: ["$monthlyIncome", 0] }, 1, 0] } },
            unemployed: { $sum: { $cond: [{ $eq: ["$monthlyIncome", 0] }, 1, 0] } }
        }}
      ],
      "topCity": [
        { $group: { _id: "$city", count: { $sum: 1 } } },
        { $sort: { count: -1 } },
        { $limit: 1 }
      ]
  }}
])
Real question answered: "I need one dashboard showing: user distribution by role, employment rate, and the city with the most trainees" — all in a single query instead of three.

Section Eleven

$bucket — Progress Level Groups

db.users.aggregate([
  { $match: { role: "trainee" } },
  { $bucket: {
      groupBy: "$completedCourses",
      boundaries: [0, 5, 10, 15],
      default: "Advanced",
      output: { count: { $sum: 1 }, names: { $push: "$name" } }
  }}
])

Result:

{ "_id": 0,  "count": 1, "names": ["Youssef Adel"] }               // Beginner (0-4 courses)
{ "_id": 5,  "count": 3, "names": ["Ahmed", "Nourhan", "Karim"] }  // Intermediate (5-9)
{ "_id": 10, "count": 1, "names": ["Mona Khalil"] }                // Advanced (10-14)

Section Twelve

$merge — Monthly Snapshot Reports

db.users.aggregate([
  { $match: { role: "trainee" } },
  { $group: {
      _id: "$track",
      totalActive: { $sum: { $cond: ["$isActive", 1, 0] } },
      employmentRate: { $avg: { $cond: [{ $gt: ["$monthlyIncome", 0] }, 1, 0] } }
  }},
  { $merge: { into: "monthlyReports", whenMatched: "replace" } }
])
Real scenario: run this pipeline every month to persist a snapshot into a monthlyReports collection, tracking how the employment rate evolves over time.

Section Thirteen

Indexes on the Users Collection

Unique Index — Prevent Duplicate Registration

db.users.createIndex({ email: 1 }, { unique: true })
If someone tries registering with an email already on the platform, the database itself rejects the operation.

Compound Index — The Most Common Admin Filter

db.users.createIndex({ role: 1, track: 1, isActive: 1 })
The most frequent query in the admin dashboard is "get all active trainees in a given track." This index makes it instant even with thousands of users.
// Query that benefits from this index
db.users.find({ role: "trainee", track: "MERN Stack", isActive: true })

Sparse Index — Since Admins & Mentors Have No Track

db.users.createIndex({ track: 1 }, { sparse: true })
Hossam Admin has track: null. A sparse index skips users without a track instead of indexing them all under a repeated null value.

Partial Index — Only on Inactive Trainees

db.users.createIndex(
  { joinDate: 1 },
  { partialFilterExpression: { isActive: false } }
)
A recurring "trainees who went inactive" report filtered by join date only needs an index covering inactive users — saving significant space versus indexing all 10,000+ users.

Verifying Index Effectiveness

db.users.find({ role: "trainee", track: "MERN Stack", isActive: true }).explain("executionStats")

If the result shows "stage": "IXSCAN", the compound index is being used. If it shows "stage": "COLLSCAN", it means a full collection scan happened instead.
