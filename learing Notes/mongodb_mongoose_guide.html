Level One

Absolute Fundamentals

1. What Is MongoDB?

MongoDB is a NoSQL document database — instead of storing data in tables and rows like SQL, it stores data as JSON-like documents (called BSON internally) inside collections. Each document can have its own structure, with no rigid schema enforced at the database level.

MongoDB is designed for flexibility and scalability — you can store a user with 2 fields next to a user with 10 fields in the same collection, with no migration required.

// A document in MongoDB
{
  "_id": "6a26898e51652b3ff6ba0fdb",
  "name": "ashraf gad",
  "email": "ashraf@gmail.com",
  "gender": "male",
  "createdAt": "2026-06-08T09:21:18.506Z"
}

4. What Is Mongoose?

Mongoose is an ODM (Object Data Modeling) library for MongoDB in Node.js. It provides a layer on top of the raw MongoDB driver, adding structure through Schemas, validation, middleware, and helper methods — so you work with JavaScript objects instead of raw MongoDB queries.

Analogy: if MongoDB is the database, Mongoose is like Sequelize or Entity Framework — it maps your JavaScript objects to database documents and handles the communication in between.

5. Connecting to MongoDB

import mongoose from 'mongoose';

const connectDB = async () => {
  try {
    await mongoose.connect('mongodb://localhost:27017/myDB');
    console.log('Database Connected Successfully ✅');
  } catch (error) {
    console.error('Database Connection Failed ❌', error);
  }
};

export default connectDB;
Tip
  • The database name (myDB) at the end of the connection string is created automatically by MongoDB the first time you insert data — no need to create it manually.

Schema & Models

6. Schema

A Schema defines the structure of a document — what fields exist, their types, and any validation rules. It's your blueprint for every document in a collection.

import mongoose from 'mongoose';

const userSchema = new mongoose.Schema({
  name:     { type: String,  required: true },
  email:    { type: String,  required: true, unique: true },
  password: { type: String,  required: true },
  age:      { type: Number },
  gender:   { type: String,  enum: ['male', 'female', 'not specified'], default: 'not specified' }
}, { timestamps: true });

9. Model

A Model is a class compiled from a Schema — it's the actual interface you use to interact with a collection. Every CRUD operation goes through the model.

const User = mongoose.model('User', userSchema);
// Creates (or uses) a collection named 'users' (Mongoose auto-pluralises)

export default User;
Naming convention: the model name is singular and PascalCase ('User'); Mongoose automatically maps it to a lowercase plural collection (users).

CRUD Operations

10. Create

Insert one document:

const user = await User.create({ name: 'Ashraf', email: 'a@gmail.com', password: '1234' });

Insert multiple documents (Array):

const users = await User.create([
  { name: 'Ahmed', email: 'ahmed@gmail.com', password: '1234', gender: 'male' },
  { name: 'Sara',  email: 'sara@gmail.com',  password: '1234', gender: 'female' }
]);
Tip
  • User.create() accepts both a single object and an array — no need to switch between create() and insertMany(). Both run Schema validation before saving.

11. Read

MethodReturnsUsage
User.find()Array (empty [] if none)Get all documents, or filter by condition
User.findOne(filter)Object or nullGet first matching document
User.findById(id)Object or nullGet document by its _id
 
// All users
await User.find();

// Filter: male users only
await User.find({ gender: 'male' });

// Find by email
await User.findOne({ email: 'ashraf@gmail.com' });

// Find by _id
await User.findById('6a26898e51652b3ff6ba0fdb');

12. Update

// Update by ID — returns the updated document (new: true)
await User.findByIdAndUpdate(
  '6a26898e51652b3ff6ba0fdb',
  { $set: { name: 'Ashraf Alaa' } },
  { new: true }
);

// Update by any field
await User.findOneAndUpdate(
  { email: 'ashraf@gmail.com' },
  { $set: { gender: 'male' } },
  { new: true }
);
Important: always use $set when updating — without it, MongoDB replaces the entire document with only the fields you sent, silently wiping any fields you didn't include.

13. Delete

// Delete by ID — returns the deleted document
await User.findByIdAndDelete('6a26898e51652b3ff6ba0fdb');

// Delete by any field
await User.findOneAndDelete({ email: 'ashraf@gmail.com' });

Query Details

14. Query Filters

Filters are plain JavaScript objects passed to find() or findOne() to narrow down results.

// Exact match
await User.find({ gender: 'male' });

// Multiple conditions (AND)
await User.find({ gender: 'male', age: 22 });

// Using operators
await User.find({ age: { $gte: 20, $lte: 30 } });  // age between 20 and 30

15. Projection

Projection controls which fields are returned — useful for hiding sensitive data like passwords or reducing response size.

// Show only name and email (1 = include)
await User.find({}, { name: 1, email: 1 });

// Hide password (0 = exclude)
await User.find({}, { password: 0 });

// Hide _id as well
await User.find({}, { name: 1, email: 1, _id: 0 });

16. Sort, Limit & Skip

// Sort by name A→Z (1 = asc, -1 = desc)
await User.find().sort({ name: 1 });

// Get only 10 results
await User.find().limit(10);

// Skip first 10 (useful for pagination)
await User.find().skip(10).limit(10);

// Combine all (page 2, sorted by createdAt newest first)
await User.find().sort({ createdAt: -1 }).skip(10).limit(10);

18. ObjectId & _id

Every MongoDB document gets an _id field automatically — a unique 12-byte identifier called an ObjectId, represented as a 24-character hex string. It is MongoDB's equivalent of a Primary Key in SQL, but globally unique across all machines and time.

6a26898e51652b3ff6ba0fdb
└───────┘└──────────┘└──────┘
  4 bytes   5 bytes   3 bytes
 timestamp  random    counter
SQL Primary KeyMongoDB ObjectId
FormatInteger (1, 2, 3 …)24-char hex string
Generated byDatabase auto-incrementClient or server (before insert)
Contains timestampNoYes — extractable via .getTimestamp()
Global uniquenessOnly within one tableGlobally unique across all servers
 
// Validate an ID before querying
import mongoose from 'mongoose';
mongoose.Types.ObjectId.isValid('6a26898e51652b3ff6ba0fdb'); // true
mongoose.Types.ObjectId.isValid('123');                       // false
Tip
  • Always validate the ID format in your controller before hitting the database — passing an invalid ID format throws a CastError from Mongoose, which you'd otherwise have to handle in the catch block.

19. Relationships (populate)

MongoDB doesn't have JOINs, but Mongoose's populate() simulates them by replacing an ObjectId reference field with the actual document from the referenced collection.

// Post schema — references User
const postSchema = new mongoose.Schema({
  title:  String,
  userId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true }
});

// Query with populate — replaces userId with the full User document
const post = await Post.findById(id).populate('userId', 'name email');
// Result: post.userId is now { name: 'Ashraf', email: 'a@gmail.com' }
// instead of just the raw ObjectId string
Performance note: populate() runs a second database query under the hood. For high-volume data, consider embedding the needed fields directly in the document instead.

20. Timestamps

Passing { timestamps: true } as a Schema option instructs Mongoose to automatically add and manage two fields on every document — createdAt and updatedAt — with no manual work required.

const userSchema = new mongoose.Schema({ name: String }, { timestamps: true });

// Every saved document automatically gets:
// createdAt: 2026-06-08T09:21:18.506Z  ← set once on insert
// updatedAt: 2026-06-08T10:00:00.000Z  ← updated on every save/update

21. create() vs. save()

create()new Model() + save()
StepsOne stepTwo steps
Modify before savingNot directlyYes — manipulate the instance first
ValidationYesYes
Best forStraightforward insertsWhen you need to transform data before saving
 
// create() — one step
const user = await User.create({ name: 'Ashraf', email: 'a@gmail.com', password: '1234' });

// save() — two steps, allows modification in between
const user = new User({ name: 'Ashraf', email: 'a@gmail.com', password: '1234' });
user.name = user.name.toUpperCase();  // modify before saving
await user.save();

22. Middleware (Hooks)

Mongoose middleware (also called hooks) are functions that run automatically before or after a specific operation — such as hashing a password before saving, or cleaning up related documents after deletion.

// pre-save hook — runs before every .save() or .create()
userSchema.pre('save', async function (next) {
  // 'this' refers to the document being saved
  if (this.isModified('password')) {
    this.password = await bcrypt.hash(this.password, 10);
  }
  next();
});

// post-save hook — runs after the document is saved
userSchema.post('save', function (doc) {
  console.log('User saved:', doc.email);
});
Tip
  • Pre-hooks receive a next callback — always call it at the end, or the operation will hang indefinitely.
  • Common use cases: password hashing (pre-save), sending a welcome email (post-save), cascading deletes (pre-deleteOne).
